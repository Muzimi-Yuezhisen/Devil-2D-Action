模块总览

这个模块解决什么问题？

  • 把角色所有数值封装成可序列化的 Stat（基础值 + 可叠加的 Modifier 列表）
  • 按 Major / Offense / Defense / Resource 四组组织属性，挂在 Entity_Stats 上
  • 提供战斗用的衍生公式：物理伤害、元素伤害、护甲减免、闪避、最大生命等
  • 用 Stat_SetupSO 配置初始 base 值；用 Object_Buff 临时 Add/Remove Modifier

你可以把这个模块想象成三层：

层职责代表脚本
数据层单个数值的存储与 lazy 求和Stat.cs
分组层把 Stat 按用途归类；SO 存默认值Stat_*Group.cs、Stat_SetupSO.cs
计算层主属性衍生 + 战斗公式 + Buff 路由Entity_Stats.cs、Object_Buff.cs
Stat_SetupSO（ScriptableObject 配置初始 base 值） → Entity_Stats.ApplyDefaultStatSetup() 写入各 Stat.SetBaseValue() → 战斗中 Entity_Combat / 技能生成物 调用 GetAttackData(DamageScaleData) → 内部 GetPhysicalDamage / GetElementalDamage（带 scale） → 组装 ElementalEffectData 供状态效果使用 → Entity_Health 调用 GetArmorMitigation / GetEvasion / GetMaxHealth → Object_Buff 碰撞后 AddModifier(source=buffName) → 等待 duration → RemoveModifier → Destroy
主属性衍生（代码中硬编码，不经过 Modifier）：
力量 Strength → 每点 +1 物理伤害，+0.5% 暴击伤害
敏捷 Agility → 每点 +0.5% 闪避，+0.3% 暴击率
智力 Intelligence → 每点 +1 元素伤害，+0.5% 全元素抗性
体质 Vitality → 每点 +5 最大生命，+1 护甲

公式速查卡

Stat 最终值

GetValue() = baseValue + Σ modifier.value（lazy 缓存，Modifier 变动后下次 GetValue 重算）

GetAttackData(DamageScaleData scaleData)

return new AttackData(this, scaleData) → physical = GetPhysicalDamage(out isCrit, scaleData.physical) → elemental = GetElementalDamage(out element, scaleData.elemental) → effectData = new ElementalEffectData(this, scaleData)

普攻传入 Entity_Combat.basicAttackScale；技能碎片传入解锁后的 Skill_Base.damageScaleData。

GetPhysicalDamage(out isCrit, scaleFactor=1)

totalBaseDamage = damage + strength critChance = critChance + agility × 0.3 critPower = (critPower + strength × 0.5) / 100 isCrit = Random(0, 100) < critChance finalDamage = isCrit ? totalBaseDamage × critPower : totalBaseDamage return = finalDamage × scaleFactor

GetElementalDamage(out element, scaleFactor=1)

取 fire / ice / lightning 中最高的一项为主元素（100% 伤害） 其余两项各贡献 50%（主元素自身不计入 50% 部分） finalDamage = 主元素 + intelligence + 次元素×0.5 之和 若最高元素 ≤ 0 → element=None, return 0 return = finalDamage × scaleFactor

GetElementalResistance(element)

baseResistance = fireRes / iceRes / lightningRes（按元素） bonusResistance = intelligence × 0.5 resistance = Clamp(base + bonus, 0, 75) / 100 return 0~0.75 的小数（75% 上限）

GetArmorMitigation(armorReduction)

totalArmor = armor + vitality effectiveArmor = totalArmor × Clamp(1 - armorReduction, 0, 1) mitigation = effectiveArmor / (effectiveArmor + 100) return = Clamp(mitigation, 0, 0.85) // 最大 85% 减伤

GetArmorReduction / GetEvasion / GetMaxHealth

GetArmorReduction() = armorReduction / 100 // 穿透比例 0~1 GetEvasion() = Clamp(evasion + agility×0.5, 0, 85) // 百分比 0~85 GetMaxHealth() = maxHealth + vitality × 5

Stat.cs

Assets/Scripts/StatSystem/Stat.cs
Serializable 类

每个游戏数值（伤害、护甲、力量等）都是一个 Stat 实例。Inspector 里可见 baseValue 和 modifiers 列表；运行时通过 GetValue() 得到最终值。

Stat 私有字段

字段类型作用
baseValuefloat基础值；由 SetBaseValue 或 ApplyDefaultStatSetup 写入，不含 Modifier
modifiersList<StatModifier>所有加成/减益条目；同 source 可有多条
needToCalculatebool脏标记：Modifier 或 base 变动后为 true，下次 GetValue 重算
finalValuefloat缓存的上次计算结果，避免每帧重复求和

StatModifier（Stat 的内部类）

[Serializable] public class
成员类型作用
valuefloat加成数值，可正可负；直接加算到 baseValue 上（非百分比乘算）
sourcestring来源标识字符串；RemoveModifier(source) 时按此匹配并移除所有同 source 的条目
StatModifier(value, source)构造函数创建一条 Modifier 并赋值 value、source

Stat 方法

方法签名做什么
AddModifier (float value, string source) new 一个 StatModifier 加入 modifiers 列表；设置 needToCalculate = true。Buff、装备、技能等临时加成均走此入口。
RemoveModifier (string source) modifiers.RemoveAll(m => m.source == source)，移除该 source 的全部 Modifier；标记需重算。
GetValue () → float 若 needToCalculate 为 true，调用 GetFinalValue() 写入缓存并清脏标记；返回 finalValue。对外读取属性的唯一公开入口。
SetBaseValue (float value) 直接设置 baseValue（表达式体：baseValue = value）。注意：当前实现未设 needToCalculate，若 base 在运行时改动且已有缓存，需手动触发重算或先改 Modifier 逻辑。
GetFinalValue () → float · private 实际求和：finalValue = baseValue，遍历 modifiers 逐项 += modifier.value，返回结果。公式：baseValue + Σ modifier.value。

方法（含完整公式说明）

方法参数 / 返回值做什么（含公式）
GetPhysicalDamage out bool isCrit, float scaleFactor=1 → float 物理伤害 + 暴击判定。
1. totalBaseDamage = offense.damage.GetValue() + major.strength.GetValue()
2. critChance = offense.critChance.GetValue() + major.agility.GetValue() × 0.3
3. critPower = (offense.critPower.GetValue() + major.strength.GetValue() × 0.5) / 100
4. isCrit = Random.Range(0, 100) < critChance
5. finalDamage = isCrit ? totalBaseDamage × critPower : totalBaseDamage
6. return finalDamage × scaleFactor
scaleFactor 来自 DamageScaleData.physical（经 GetAttackData / AttackData）；普攻常见为 1。
GetAttackData DamageScaleData → AttackData return new AttackData(this, scaleData)：组装物理、元素、暴击、主元素类型与 ElementalEffectData。
GetElementalDamage out ElementType element, float scaleFactor=1 → float 元素伤害：最高元素为主，其余各 50%，再加智力 flat 加成。
1. 读 fire / ice / lightning 三项 GetValue()，以及 bonusElementalDamage = intelligence.GetValue()
2. 取三者最大值为主元素，element 设为 Fire / Ice / Lightning
3. 若 highestDamage ≤ 0 → element = None，return 0
4. 非主元素各贡献 该元素值 × 0.5（主元素对应项为 0）
5. finalDamage = highestDamage + bonusElementalDamage + weakerElementsDamage
6. return finalDamage × scaleFactor（来自 DamageScaleData.elemental；普攻场景常见 ≈0.4）
GetElementalResistance ElementType element → float 指定元素的抗性，返回 0~0.75 的小数。
1. switch element → baseResistance = fireRes / iceRes / lightningRes 的 GetValue()
2. bonusResistance = major.intelligence.GetValue() × 0.5
3. resistance = baseResistance + bonusResistance
4. finalResistance = Clamp(resistance, 0, 75) / 100（硬上限 75%）
Entity_Health 用 damage × (1 - finalResistance) 减免元素伤害。
GetArmorMitigation float armorReduction → float 护甲减伤比例，返回 0~0.85。
1. totalArmor = defense.armor.GetValue() + major.vitality.GetValue()（体质 1:1 加护甲）
2. reductionMultiplier = Clamp(1 - armorReduction, 0, 1)（armorReduction 为 0~1 穿透比例）
3. effectiveArmor = totalArmor × reductionMultiplier
4. mitigation = effectiveArmor / (effectiveArmor + 100)（递减回报，100 为 magic number）
5. return Clamp(mitigation, 0, 0.85)（最大 85% 物理减伤）
攻击方传入的 armorReduction 来自 GetArmorReduction()。
GetArmorReduction () → float 攻击方护甲穿透比例。
return offense.armorReduction.GetValue() / 100
例如 Inspector 里 armorReduction=30 → 返回 0.3，目标有效护甲 ×0.7。
GetEvasion () → float 闪避概率（百分比数值，非小数）。
1. totalEvasion = defense.evasion.GetValue() + major.agility.GetValue() × 0.5
2. return Clamp(totalEvasion, 0, 85)（上限 85%）
Entity_Health：Random.Range(0, 100) < GetEvasion() 则攻击被闪避。
GetMaxHealth () → float 最大生命值。
return resources.maxHealth.GetValue() + major.vitality.GetValue() × 5
Entity_Health.Awake 用其初始化 currentHealth。
GetStatByType StatType type → Stat 按枚举返回对应 Stat 引用，供 Buff 等系统 AddModifier / RemoveModifier。
switch 覆盖 StatType 全部 19 个值；default 打 Warning 并 return null。
不复制 Stat，返回同一实例，Modifier 会直接影响该实体属性。
ApplyDefaultStatSetup () · [ContextMenu] 把 defaultStatSetup SO 中所有 float 写入各 Stat.SetBaseValue。
若 defaultStatSetup 为 null → Log 并 return。
顺序：resources → major → offense（含三元素）→ defense（含三抗性）。
仅改 baseValue，不清除已有 Modifier。Inspector 右键组件名可触发。

常见问题

Modifier 的 source 是什么？有什么用？

source 是任意字符串标签，标识「这条加成从哪来」。RemoveModifier(source) 会删除所有 modifier.source == source 的条目。Object_Buff 用 Inspector 里的 buffName 作为 source，这样 duration 结束时一次 Remove 就能清掉该 Buff 物体加上的全部属性。不同系统应使用不同 source（如 "FirePotion"、"SkillTree_Damage"），避免误删他人 Modifier。

ApplyDefaultStatSetup 什么时候调用？会清 Buff 吗？

在 Editor 中：选中带 Entity_Stats 的对象 → 组件右上角 ⋮ → Update Default Stat Setup（ContextMenu）。或在 Play 前/代码里手动调用。它只执行各 Stat 的 SetBaseValue，不会清除 modifiers 列表。若需要「完全重置」，需额外 RemoveModifier 或重建 Stat 列表。记得先把 defaultStatSetup 字段拖入 SO 资产。

主属性加成和 Modifier 有什么区别？

Modifier 通过 AddModifier 加在单个 Stat 的 base 上（如直接 +10 damage）。主属性（strength/agility 等）的衍生加成写在 Entity_Stats 的各个 GetXxx 公式里，不自动变成 Modifier。例如 +5 力量不会出现在 offense.damage 的 modifiers 里，但在 GetPhysicalDamage 里会 +5 伤害。给主属性加 Buff 应使用 StatType.Strength 等对 major.strength AddModifier。

暴击率 / 暴击伤害 / 抗性 / 穿透的单位？

Inspector 与 SO 里多为「百分比整数」：critChance=15 表示 15%；critPower=150 表示 150% 暴击倍率（代码里 /100）。armorReduction、evasion、各 Res 同理为百分比。GetArmorMitigation 返回 0~1 小数；GetElementalResistance 返回 0~0.75 小数；GetEvasion 返回 0~85 的百分比数值。

Buff 拾取后 NullReference

检查：① 碰撞对象是否有 Entity_Stats；② buff.type 是否在 GetStatByType 中有实现；③ buffName 非空（Remove 时也要用同一字符串）。OnTriggerEnter2D 未判 statsToModify 为 null，玩家无 Entity_Stats 会报错。

StatType.CritChange 拼写

枚举名为 CritChange（非 CritChance），与 offense.critChance 对应。Buff 配置时需选 CritChange，勿与 CritPower 混淆。

元素伤害为何有时为 0？

GetElementalDamage 要求 fire/ice/lightning 至少一项 > 0 才输出伤害；全为 0 时 element=None、return 0。仅智力不加元素伤害（智力 flat 加在已有主元素之后）。次元素 50% 规则：三项中最高为主，另外两项各算一半叠加。

与战斗模块的衔接

Entity_Combat.PerformAttack 调用 GetAttackData(basicAttackScale)；技能生成物同样用 GetAttackData(damageScaleData)。防守方仍用 GetArmorMitigation / GetElementalResistance / GetEvasion。详见模块 5、模块 8。
