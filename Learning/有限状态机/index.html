模块总览

解决什么问题？ 让角色在任意时刻只处于一种行为模式（idle / move / attack…），切换时统一走 Enter → Update → Exit，避免逻辑互相打架。

  • 同一时刻只有一个 currentState 在运行（不能同时「攻击」又「跳跃」）
  • 换状态时先 Exit 旧状态，再 Enter 新状态
  • 动画 Bool、计时器 stateTimer、动画结束标记 triggerCalled 都在状态层处理
  • StateMachine 不是 MonoBehaviour，由 Entity.Awake 里 new StateMachine() 创建
struct.pdf 要点：FSM 便于加新状态、调试隔离、避免冲突行为。你之前自己写过状态机的话，这里的类名只是作者的具体实现。

状态切换流程

Entity.Update() 每帧 → stateMachine.UpdateActiveState() → currentState.Update() → stateTimer -= deltaTime → UpdateAnimationParameters() → 检测条件（输入、碰撞、timer…） → stateMachine.ChangeState(新状态) → if (canChangeState == false) return → currentState.Exit() // anim.SetBool(name, false) → currentState = 新状态 → currentState.Enter() // anim.SetBool(name, true) 动画事件 (Animation Event) → Entity_AnimationTriggers.CurrentStateTrigger() → entity.CurrentStateAnimationTrigger() → currentState.AnimationTrigger() // triggerCalled = true

字段

名称类型作用

canChangeStatebool是否允许 ChangeState；false 时切换被忽略

函数

函数何时调用做什么
Init(entityState)Player/Enemy 的 Start() 里，游戏开始时canChangeState = true；currentState = 传入状态；调用 currentState.Enter() 进入初始状态（如 idle）
ChangeState(entityState)各状态 Update() 里满足条件时若 canChangeState 为 false 则 return；否则 currentState.Exit() → 赋值新状态 → Enter()
UpdateActiveState()Entity.Update() 每帧调用 currentState.Update()，驱动当前状态逻辑
SwitchOffStateMachine()Enemy_DeadState.Enter 等需要「锁死」时canChangeState = false；之后所有 ChangeState 无效，状态机不再切换
注意：StateMachine 没有 IDisposable 自动清理；项目依赖 Entity 生命周期。若扩展场景卸载逻辑，需在适当时机停止 Update。

常见问题

ChangeState 没反应？

检查 canChangeState 是否为 false（敌人死亡后 SwitchOffStateMachine）。检查是否在 Exit/Enter 里又 ChangeState 导致逻辑混乱。

攻击动画播不完就切状态？

确认动画末尾有 CurrentStateTrigger 事件，且状态 Update 里是等 triggerCalled 再 ChangeState，而不是只看 timer。

Enter/Exit 和 Unity 的 OnEnable 有什么区别？

OnEnable 是 GameObject 启用时调用；状态的 Enter/Exit 是逻辑状态切换时调用，一个物体可以一直 Enable 但状态从 idle 变 move。
