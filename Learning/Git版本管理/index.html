Git 版本管理

工程工具栏目 · 结合本仓库 devil 的实际用法 · 简历可写的「Git 使用经验」从这里练起

课程模块 1–8 Git 版本管理

为什么简历常写「熟悉 Git」

公司协作几乎都用 Git。面试官想确认你会：

  • 把改动拆成清晰的 commit（可回溯、可 Code Review）
  • 用 branch 做功能开发，不直接在混乱的主线上乱改
  • 和远端（GitHub / GitLab）push / pull，不丢本地成果
  • 知道什么该进仓库、什么不该（Unity 的 Library 等）

本页目标：你能在 devil 项目上独立完成「存盘 → 提交 → 推远端」全流程，并在简历上写得出具体场景。

核心概念（用项目语言理解）

概念是什么在本项目里
仓库 Repository被 Git 跟踪的整个项目文件夹d:\Unity\Projects\devil，根目录有 .git/
工作区 Working tree你正在改的文件Unity / VS 里打开的 Assets、脚本
暂存区 Staginggit add 后等待提交的清单决定「这一笔 commit 包含哪些文件」
提交 Commit一次带说明的快照例如「接好 SkillObject_Shard Prefab」
分支 Branch平行的开发线默认 main；做大功能时可开 feature/xxx
远端 RemoteGitHub 等网上的备份仓库origin（配置后）
.gitignore告诉 Git 忽略哪些路径已忽略 Library、Temp、Logs 等
改文件（Unity Ctrl+S） → git add（放入暂存区） → git commit（本地历史多一笔） → git push（备份到 GitHub）

本项目现状（已初始化）

  • 已执行 git init，默认分支 main
  • 已有 .gitignore / .gitattributes
  • 已有首次提交：基线快照（Assets、Packages、ProjectSettings、Learning 等）
  • 尚未必须配置 GitHub；没有 push 也能在本机用 commit 防丢
重要：Git 只保存已写入磁盘的文件。Unity 场景必须先 Ctrl+S，再 git add / commit。未保存的场景崩溃后，Git 也救不回来。

日常工作流（Unity 推荐节奏）

做完一小块功能时

1. Unity：Ctrl+S 保存 Scene / Prefab 2. 终端进入项目根目录 3. git status ← 看改了什么 4. git add . ← 或只 add 相关路径 5. git commit -m "…" ← 写清楚「为什么 / 做了什么」 6.（可选）git push

好的 commit 信息示例

较差较好
updateAdd SkillObject_Shard explode VFX on hit
fixFix UI_TreeNode unlock when skillManager is null
今天的Wire UI_SkillTree parentNodes for three skill roots

中英文均可；关键的是以后自己能看懂。简历/面试时可以说：「我用语义化 commit 记录功能点」。

常用命令速查

在 PowerShell / Cursor 终端中，先：

cd d:\Unity\Projects\devil

查看状态

命令作用
git status哪些改了、哪些已暂存、当前分支
git status -sb短格式状态
git log --oneline -10最近 10 条提交
git diff工作区相对暂存区的差异
git diff --staged已暂存、即将提交的差异

保存进度

命令作用
git add .暂存当前目录下所有改动（受 .gitignore 约束）
git add Assets/Scripts/UI/只暂存某一文件夹
git commit -m "说明"生成一次本地提交

撤销（安全向）

命令作用注意
git restore 文件丢弃工作区未暂存修改改动会丢，慎用
git restore --staged 文件取消暂存，文件内容保留较安全
git reset --soft HEAD~1撤销上一次 commit，改动留在暂存区未 push 时可用
入门阶段避免：git reset --hard、git push --force。容易不可逆丢掉工作。

分支基础（简历加分点）

大功能不要全堆在 main 上乱改；开分支做完再合并，是团队标配。

git checkout -b feature/skill-shard → 开发、多次 commit → git checkout main → git merge feature/skill-shard →（可选）删除功能分支
命令作用
git branch列出本地分支
git checkout -b feature/xxx创建并切换到新分支
git checkout main切回主分支
git merge feature/xxx把功能分支合进当前分支

练习建议

下次改技能树时：git checkout -b feature/skill-tree-layout → 改完 commit → 切回 main merge。简历可写：「独立使用 feature 分支开发与合并」。

远端与 GitHub（真正的「云备份」）

  1. 注册 GitHub，新建 Private 空仓库（不要勾选自动生成 README，避免冲突）
  2. 本地关联并推送：
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
命令作用
git remote -v查看已配置的远端地址
git push把本地提交推到远端
git pull拉取远端更新并合并到本地
git clone 地址另开电脑时完整下载仓库
首次 push 可能要登录 GitHub（浏览器 / Personal Access Token）。私有仓库不会公开你的游戏资源。

Unity 项目专用注意

要点说明
必提交Assets/、Packages/、ProjectSettings/、以及本仓库的 Learning/
勿提交Library/、Temp/、Logs/、UserSettings/（已在 .gitignore）
场景 / Prefab改完必须存盘，再 commit；否则历史里没有
meta 文件和资源成对提交，不要只交脚本不交 .meta
一人项目仍建议频繁 commit；崩溃或误删时可 git checkout / 看历史恢复

练习清单（做完再写简历更踏实）

  1. Unity 随意改一个无关紧要的注释 → 存盘 → git status 看到变化
  2. git add + git commit -m "…" → git log --oneline 看到新记录
  3. 开分支 feature/practice，再改一点，merge 回 main
  4. （推荐）创建 GitHub 私有库并 push 一次
  5. 故意改坏一个已跟踪文件，用 git restore 恢复，体会「可回溯」

常见问题

commit 后还能改说明吗？

最近一次且未 push 时可用 amend，但容易搞乱；入门阶段再 commit 一笔修正更安全。

为什么 git status 里没有 Library？

被 .gitignore 忽略了，这是正确行为。换电脑克隆后，Unity 打开项目会重新生成 Library。

Cursor / VS 里能不能不打命令？

可以。左侧 Source Control 面板：点 + 暂存 → 写 message → Commit。原理与命令行相同，简历仍算 Git 经验。

和上次强制重启丢场景有关吗？

有。习惯变成「Ctrl+S → commit」，至少本机历史里有；再加 GitHub push，换机也能拉回。
