模块总览

这个模块解决什么问题？

  • 在 Player 身上维护真实技能对象（如 Skill_Dash），而不是只在 UI 上显示
  • 统一管理冷却：能不能放技能、什么时候进入 CD
  • 接收技能树解锁的升级数据（UpgradeData）：升级分支 + 新冷却时间
  • 为每种大技能（Dash、未来的 TimeEcho）提供可扩展的子类行为
和模块 2、7 的分工：
· 模块 7 技能树 UI：点节点、扣技能点、调用 SetSkillUpgrade
· 本模块：Player 上的 Skill_Base 组件存 CD 与 upgradeType
· 模块 2 Player_DashState：冲刺的移动、重力、时长（不是 Skill_Dash 写的）

三层架构

【配置层】Skill_DataSO + UpgradeData 挂在 UI_TreeNode 上，描述「这个节点解锁后给什么升级」 ↓ 解锁时 SetSkillUpgrade 【运行时层】Skill_Base → Skill_Dash（挂在 Player 子物体） 冷却 lastTimeUsed / cooldown、upgradeType、各技能专属效果 ↑ GetSkillByType 【调度层】Player_SkillManager（挂在 Player 上） 给 UI 和状态机一个统一入口：SkillType → Skill_Base
层脚本职责
配置Skill_DataSO, UpgradeData编辑器资源，不进 Play 逻辑
运行时Skill_Base, Skill_DashPlay 时真正存在的技能组件
调度Player_SkillManager查找、分发技能引用

流程 A：技能树解锁（配置 → 运行时）

玩家点击 UI_TreeNode（满足技能点 / 前置 / 非互斥） → Unlock() → skillTree.skillManager.GetSkillByType(skillData.skillType) → Skill_Base.SetSkillUpgrade(skillData.upgradeData) → upgradeType = upgrade.upgradeType → cooldown = upgrade.cooldown

解锁不会自动改 Player.dashSpeed / dashDuration，目前只改技能组件上的 CD 和 升级分支标记。

流程 B：按键释放 Dash（冷却 + 状态机）

任意 PlayerState.Update()（模块 2） → input.Player.Dash 本帧按下 && CanDash() → skills.dash.CanUseSkill() // Skill_Base：是否在 CD → 非贴墙、当前非 dashState → skills.dash.SetSkillOnCooldown() // lastTimeUsed = Time.time → ChangeState(player.dashState) // 模块 2：位移与动画 Player_DashState.Enter → dashDir、gravityScale=0、stateTimer=dashDuration → （当前未调用）Skill_Dash.OnStartEffect()

Player 上的 Hierarchy 建议

Player ├── Player_SkillManager ← GetComponentInChildren 找技能 ├── …其他组件（Entity、Combat、Health） └── Skills（或任意子物体名） └── Skill_Dash ← Skill_Dash : Skill_Base 组件

Player_SkillManager.Awake 用 GetComponentInChildren<Skill_Dash>()，子物体可在任意深度，但场景里必须有一个 Skill_Dash 组件。

函数

函数何时调用做什么
Awake()组件初始化virtual：lastTimeUsed = lastTimeUsed - cooldown → 等价于 -cooldown，让游戏开始时不在 CD 上
SetSkillUpgrade(upgrade)UI_TreeNode.UnlockupgradeType = upgrade.upgradeType；cooldown = upgrade.cooldown
CanUseSkill()PlayerState.CanDash若 OnCooldowm() 为 true 则 Log 并 return false；否则 true
OnCooldowm()CanUseSkill 内部private：Time.time < lastTimeUsed + cooldown
SetSkillOnCooldown()PlayerState 确认释放 Dash 时lastTimeUsed = Time.time，开始计时
RestCooldownBy(reduction)未来（如 Healing wisp）lastTimeUsed += reduction，等效减少剩余 CD
RestCooldown()未来满重置 CDlastTimeUsed = Time.time，立即视为刚用过（需配合逻辑理解；也可理解为重置基准）
Awake 技巧：lastTimeUsed 默认 0，减 cooldown 后为负数。例如 cooldown=3 → lastTimeUsed=-3，则 CD 结束时刻为 0，开局 Time.time≥0 即可用。

常见问题

树上解锁了「克隆冲刺」，游戏里没克隆？

正常。unlock 只写了 upgradeType，OnStartEffect() 没有任何地方调用。需要在 Player_DashState.Enter 接上。

技能系统和 Player_DashState 谁管冲刺？

分工：Skill_Base 管 CD；DashState 管移动；Skill_Dash 管升级带来的额外效果（生成物等）。

解锁后 CD 变了但手感没变？

SO 的 upgradeData 只改 Skill_Base.cooldown，不改 Player.dashSpeed / dashDuration。要改冲刺距离需改 Player 参数或扩展 UpgradeData 字段。

GetSkillByType 返回 null？

检查：SO 的 skillType 是否为已实现的 Dash；场景里是否有 Skill_Dash 子组件；TimeEcho 等未实现类型会 Log 并返回 null。

SetSkillUpgrade 参数类型报错？

传整个 skillData.upgradeData（UpgradeData 对象），不是 .upgradeType 枚举。见模块 7 FAQ。

RestCooldownBy 是干什么的？

struct.pdf 里 Healing wisp「减少其他技能 CD 1 秒」会用到。对 lastTimeUsed 做加法，相当于让冷却结束时间提前。
