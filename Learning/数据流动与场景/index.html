数据流动与场景

不按文件夹拆脚本，而是按「一件事从按键到结算」走一遍：谁调用谁、数据从哪来、检测怎么做、伤害和 Debuff 怎么落到怪身上。

怎么用这一页

课程模块 1–8 是「按系统拆开讲」。这里是反过来：先假设一个你在游戏里会做的动作，再顺着调用链看数据怎么流。

  • 每个场景先给一句「发生了什么」，再逐步拆细节
  • 多处场景会汇入同一条伤害管线（见下方），读一次就能串起普攻和技能
  • 细节公式仍以模块 5/6 为准；这里侧重「顺序」和「谁拿着数据」
建议先扫一遍「进游戏前配置」，再读场景 1 和共用伤害管线；后面场景会反复引用这两块，避免重复堆公式。

进游戏前：做了哪些配置

运行时很多「看起来像代码硬写」的东西，其实是进 Play 之前就在 Inspector / 资源里填好的。下面按「数据从哪来」列。

1. 属性与默认数值

  • Stat_SetupSO（Create → RPG Setup / Default Stat Setup）：最大生命、攻速、伤害、暴击、元素伤、护甲、抗性、力敏智体等基础值模板
  • 玩家 / 敌人上的 Entity_Stats：挂四组 Stat（resources / offense / defense / major），可用菜单「Update Default Stat Setup」从 SO 灌进基础值
  • 这些值进游戏后还会被 Buff 修正（Stat.AddModifier），但起点是这里

2. 技能数据与技能树节点

  • Skill_DataSO：显示名、图标、消耗、技能大类 skillType、是否 unlockedByDefault、以及一份 UpgradeData（升级类型、冷却、DamageScaleData）
  • 场景里技能树 UI 每个图标是 UI_TreeNode：拖入对应 SO，填前置节点 neededNodes、互斥 conflictNodes
  • 玩家层级里要有 Player_SkillManager，子物体挂 Skill_Dash / Skill_Shard（运行时真正改的是这些组件上的字段，不是 SO 本身）

3. 伤害缩放（普攻 vs 技能）

  • 普攻：Entity_Combat.basicAttackScale（Inspector 上的 DamageScaleData，例如元素倍率常设成 0.4 一类）
  • 技能：解锁时把 SO 里的 damageScaleData 写进 Skill_Base.damageScaleData
  • 两者最后都进同一条：stats.GetAttackData(scale) → AttackData

4. 碰撞与检测（范围从哪来）

  • 普攻：Entity_Combat 上的 targetCheck 点、targetCheckRadius、whatIsTarget 层级
  • 碎片爆炸：Prefab SkillObject_Shard 上的 whatIsEnemy、checkRadius（基类 SkillObject_Base）
  • 敌人找玩家：Enemy 上的 playerCheck、playerCheckDistance、whatIsPlayer
  • 地面 / 墙：Entity 上的 ground/wall Check 点与 whatIsGround
  • Unity 里还要保证 Layer、Collider、Tag 和这些 LayerMask 对得上，否则「明明贴脸却打不中」

5. 输入与状态机接线

  • Input System：PlayerInputSet（移动、跳、攻、弹反、冲刺、Spell、开技能树等）
  • Player.OnEnable：Movement → moveInput；Spell → skillManager.shard.TryUseSkill()；ToggleSkillTree → UI
  • 冲刺键不在这里绑死位移，而是各 PlayerState.Update 里读 Dash，再切 dashState
  • Animator：攻击帧调 AttackTrigger → Entity_Combat.PerformAttack；敌人攻击帧可开关弹反窗口

6. Prefab 与场景物体

  • SkillObject_Shard Prefab：拖给 Skill_Shard.shardPrefab，爆炸 VFX 拖给碎片上的 vfxPrefab
  • 敌人：Skeleton 挂状态、Health、Combat、StatusHandler、VFX；弹反警示物体挂在 Enemy_VFX.attackAlert
  • Buff 球 / 宝箱：各自组件参数（增益列表、击退等）在场景或 Prefab 上配
进 Play 前（配置） Stat_SetupSO / Entity_Stats 基础值 Skill_DataSO → UI_TreeNode Combat / Shard Prefab 的半径与 LayerMask Input Actions + Animator 事件名 ↓ 进 Play 后（运行时） 默认解锁节点 Start → Unlock → SetSkillUpgrade 玩家输入 / 动画事件 / 敌人 AI 状态 ↓ AttackData 计算 → TakeDamage → Debuff / VFX

共用伤害管线（请先读这一段）

无论是普攻还是碎片爆炸，打到可受伤目标后，核心路径几乎一样。差别只在于：谁发起检测、用哪份 DamageScaleData、伤害来源 Transform 是谁。

拿到目标 Collider → GetComponent<IDamagable>() → attackData = 攻击方.stats.GetAttackData(某份 DamageScaleData) ├─ GetPhysicalDamage → 物伤 + 是否暴击 ├─ GetElementalDamage → 元素伤 + 主元素类型 └─ new ElementalEffectData → 冰/火/电效果参数 → damagable.TakeDamage(物伤, 元素伤, 元素, 伤害来源Transform) ├─ 闪避判定 ├─ 护甲减伤（考虑攻击方穿甲） ├─ 元素抗性减伤 ├─ 击退 └─ ReduceHealth → 可能死亡 → 仅 TakeDamage 返回 true 时： ├─ 若元素 != None：StatusHandler.ApplyStatusEffect(元素, effectData) └─（普攻）VFX.CreateOnHitVFX(是否暴击, 元素)
环节谁负责你要记住的一点
算伤害数字Entity_Stats + AttackData暴击在算物伤时掷骰；元素取「最高元素为主、其它半伤」
扣血与击退Entity_Health / Enemy_Health接口是 IDamagable.TakeDamage，宝箱也能实现它
DebuffEntity_StatusHandler不是「伤害函数里写死」，而是单独 Apply；抗性会削弱效果
命中表现Entity_VFX普攻有命中特效；碎片爆炸用自己的 VFX Prefab
范围检测本身不「选目标 AI」：普攻和爆炸都是 Physics2D.OverlapCircleAll 一圈，筛有 IDamagable 的碰撞体。只有「追踪碎片」会先 FindClosestTarget 再飞过去，爆炸时仍是圆范围。

场景 1：玩家地面普攻打到怪物

情境：站在地上按攻击键，连招第一段挥刀，刀光范围内的骷髅掉血，可能暴击，可能挂上元素异常。

Attack 键 → GroundState 切到 basicAttackState → Animator 播 basicAttack，某帧 AttackTrigger → Entity_Combat.PerformAttack → OverlapCircleAll(targetCheck, radius, whatIsTarget) → 对每个目标走「共用伤害管线」（basicAttackScale） → 怪掉血 / Debuff / 命中特效；怪可能 TryEnterBattleState
  1. 按键怎么进状态机？
    Player_GroundState.Update 读到 input.Player.Attack，ChangeState(basicAttackState)。 空中则是 AiredState 进 jumpAttackState（另一套动画与位移，但攻击结算仍可走同一 Combat）。
  2. 为什么不是「按下立刻结算伤害」？
    伤害绑在动画事件上：子物体 Entity_AnimationTriggers.AttackTrigger → PerformAttack()。 这样刀刃挥到的那一帧才判定，而不是按键瞬间。
  3. 范围检测怎么做？
    Physics2D.OverlapCircleAll(targetCheck.position, targetCheckRadius, whatIsTarget)。 圆心是挂在角色上的空物体（常在武器前方），半径和 Layer 在 Combat 组件上配。 没有单独的「索敌列表」——圆里碰到谁算谁。
  4. 伤害数字从哪来？会不会暴击？
    stats.GetAttackData(basicAttackScale)： 物伤走 GetPhysicalDamage（力量加成、暴击率/暴伤掷骰，结果写入 attackData.isCrit）； 元素走 GetElementalDamage（主元素 + 弱元素半伤 + 智力）。 缩放字段把「这一刀」相对面板的倍率压下来（例如元素 0.4）。
  5. 怪物怎么收到伤害？
    目标上的 Enemy_Health 实现 IDamagable。 TakeDamage 里：闪避 → 用攻击方穿甲算护甲减免 → 元素抗性 → 击退 → ReduceHealth。 若攻击方是玩家，Enemy_Health 还会 TryEnterBattleState（挨打进战，见场景 6）。
  6. Debuff 何时挂上？
    PerformAttack 在 TakeDamage 之后，若 element != None，调目标 StatusHandler.ApplyStatusEffect(element, effectData)。 详见场景 8。
  7. 暴击有什么可见反馈？
    仅当 TakeDamage 返回 true（没闪掉）时，vfx.CreateOnHitVFX(..., isCrit, element) 生成不同命中特效预制体。

场景 2：按 Spell 放下时间碎片，炸到怪物

情境：已解锁基础 Shard。按施法键，脚下（或玩家位置）出现碎片，数秒后爆炸（或碰到怪立刻炸），范围内怪物受伤。

Spell 键（Player.OnEnable 绑定） → skillManager.shard.TryUseSkill() → CanUseSkill?（upgradeType!=None 且不在 CD） → HandleShardRegular → CreateShard → Instantiate(shardPrefab) → SetupShard 注入 playerStats + damageScaleData Invoke(Explode, detinateTime) → 定时到 / OnTriggerEnter2D(Enemy) → Explode → DamageEnemiesInRadius → 共用伤害管线 → 播爆炸 VFX，Destroy 碎片，SetSkillOnCooldown
  1. 输入入口和普攻不一样：Spell 在 Player.OnEnable 直接调技能，不经过「攻击状态」。 冲刺则是状态机；碎片是「技能组件自己 TryUse」。
  2. 解锁与冷却闸门：Skill_Base.CanUseSkill：未解锁（None）或 CD 中直接 return。 基础碎片成功放出后会进冷却（具体在分支 Handle 末尾 SetSkillOnCooldown）。
  3. 生成物带着谁的属性？
    SetupShard 把 shardManager.player.stats 和当前技能的 damageScaleData 拷进碎片。 爆炸时用玩家属性算 AttackData，不是怪物属性。
  4. 两种引爆：① Invoke(Explode, time) 定时；② 触发器碰到带 Enemy 的碰撞体立刻 Explode。 爆炸里 DamageEnemiesInRadius(transform, checkRadius) → 又是圆检测。
  5. 和普攻检测的差别：圆心是碎片位置，Layer 用 Prefab 上的 whatIsEnemy；但 damageDealer 记录真正的玩家，确保穿甲等攻击方属性可以被正确读取。

场景 3：追踪碎片如何「索敌」

情境：解锁 Shard_MoveToEnemy（或多重里也会追踪）。碎片生成后飞向最近敌人，碰到或到时再炸。

  1. 索敌算法：SkillObject_Base.FindClosestTarget： 先 OverlapCircleAll(自己, 半径10, whatIsEnemy)，再比距离，取最近 Transform。 这是简单的「最近单位」，不是仇恨列表、不是锁敌 UI。
  2. 怎么飞：MoveTowardsClosestTarget(speed) 记下 target 与 speed； Update 里 Vector3.MoveTowards 每帧靠近。仍无导航网格，直线飞。
  3. 伤害何时算：仍然要等 Explode。飞只是改变爆炸位置；结算逻辑与场景 2 相同。
  4. 冲刺带出的碎片：Skill_Dash 的起止效果也可 CreateRawShard 并指定是否移动——同一套 SetupShard(..., canMove, speed)。

场景 4：冲刺（Dash）

情境：已解锁 Dash。在可冲刺状态下按冲刺键，角色短暂高速位移，可能带残影；若升级带碎片/克隆，起止会额外造物（克隆部分可能仍是占位日志）。

任意 PlayerState.Update → Dash 键 + CanDash（技能可用、未贴墙、不在 dashState） → dash.SetSkillOnCooldown() → ChangeState(dashState) → Enter: OnStartEffect + 残影 + 锁方向 + 重力=0 → Update: 恒定 dashSpeed，撞墙可取消 → Exit: OnEndEffect + 恢复重力
  1. CD 与位移分离：冷却写在 Skill_Dash（Skill_Base）；位移在 Player_DashState。 先 SetSkillOnCooldown 再进状态，避免连按刷冲刺。
  2. OnStartEffect / OnEndEffect：按 upgradeType 决定是否在起点/终点生成碎片等。 这是「技能数据」插进「位移状态」的挂钩点。
  3. 残影：Player_VFX.DoImageEchoEffect(dashDuration) 按间隔复制当前精灵，与伤害无关。
  4. 没有单独的冲刺伤害盒：基础 Dash 本身不走 PerformAttack；伤害来自升级生成的碎片爆炸（若有）。

场景 5：弹反成功

情境：敌人攻击动画进入「可弹反窗口」，玩家按弹反键，窗口内的敌人被弹进眩晕。

敌人攻击动画事件 EnableCounterWindow → enemy.canBeStunned = true，警示图标亮 玩家 CounterAttack 键 → counterAttackState → Enter 立刻 Player_Combat.CounterAttackPerformed → OverlapCircleAll（同普攻检测圈） → 目标 ICounterable 且 CanBeCountered → HandleCounter → Skeleton 切 stunnedState（击飞、关窗口） 敌人动画 DisableCounterWindow → 窗口关闭
  1. 窗口是动画开的：EnemyAnnimationTriggers 在攻击前摇/出刀帧开窗，收招关窗。 玩家弹反检测也是圆，和普攻共用 Combat 的 targetCheck。
  2. 不走 TakeDamage：弹反是状态切换（眩晕），不是算伤害管线。 接口 ICounterable 把「能被弹」和「被弹后干什么」交给具体敌人。
  3. 失败怎么收：没弹到人时靠 stateTimer（recovery）超时回待机；弹到了等动画 triggerCalled。

场景 6：敌人如何发现玩家并进入战斗

情境：骷髅在巡逻，玩家走进视野；或玩家先普攻打中它——都会进入 Battle 追击。

  1. 巡逻时发现：Enemy_GroundedState.Update（Idle/Move 的基类）里 PlayerDetected() 为真 → battleState。 检测是朝向方向的射线：Raycast 长度 playerCheckDistance，层为 Player|Ground；命中物必须是 Player 层。
  2. 挨打进战：Enemy_Health.TakeDamage 成功后，若伤害来源带 Player， TryEnterBattleState(damageDealer)。已在 battle/attack 则忽略。
  3. 战斗里做什么：刷新「最后看见玩家」时间；过近后撤；进入 attackDistance 且仍看见玩家则 attackState； 超时没看见则回 Idle。追击用 battleMoveSpeed 朝玩家水平方向设速度。

场景 7：敌人攻击打到玩家

情境：战斗中的骷髅进入 Attack，动画帧结算，玩家掉血。

  1. 敌人同样有 Entity_Combat + 动画 AttackTrigger → PerformAttack。 whatIsTarget 配成玩家层；缩放用敌人自己的 basicAttackScale。
  2. 玩家 Entity_Health.TakeDamage：同一套闪避 / 护甲 / 抗性 / 击退。 血量归零 → EntityDeath → 玩家死亡事件 → 敌人 HandlePlayerDeath 回 Idle。
  3. 元素 Debuff 也能打到玩家（若敌人元素伤 > 0），走玩家身上的 StatusHandler 与 SlowDownEntity。

场景 8：元素 Debuff 如何释放到怪物身上

情境：玩家火焰属性较高，一刀或一次爆炸后，怪物身上闪红并持续掉血（或冰减速、电感电蓄能）。

AttackData 构造时 → GetElementalDamage 选出主元素（火/冰/电） → ElementalEffectData 用 DamageScaleData + 攻击方面板算： 冰：时长、减速倍率 火：时长、总燃烧伤害（火伤×burnDamageScale） 电：时长、落雷伤害、每次充能 shockCharge TakeDamage 之后 → ApplyStatusEffect(element, effectData) → CanBeApplied?（通常同时只挂一种；电可叠充能） → Ice: Chill 协程 + entity.SlowDownEntity → Fire: Burn 协程按 tick 扣血 → Lightning: 积蓄 currentCharge，满则落雷 Instantitate + ReduceHealth
  1. 抗性何时生效：冰缩短持续时间；火削弱燃烧总伤；电削弱本次获得的充能。 都在 StatusHandler 的 Apply* 里乘 (1 - resistance)。
  2. 和「元素瞬间伤害」的区别：元素瞬间伤在 TakeDamage 里一次性扣； Debuff 是额外的持续效果。两者可以同时发生。
  3. 表现：PlayOnStatusVfx 改精灵颜色闪烁；感电满额再播落雷 Prefab。

场景 9：进游戏后点技能树，再释放新技能

情境：开局只有默认解锁。打开技能树点亮「愤怒碎片」，扣点后按 Spell，行为变成新分支。

ToggleSkillTreeUI → 显示 UI_SkillTree 点击 UI_TreeNode → CanBeUnlocked（点数、前置、互斥） → Unlock 扣点、图标变白、锁互斥子树、连线提亮 skillManager.GetSkillByType(skillType) .SetSkillUpgrade(upgradeData) upgradeType / cooldown / damageScaleData ← 写入运行时技能 下次 Spell → TryUseSkill 走新的 Unlocked(分支) 判断
  1. SO 不会在运行时被改：改的是 Player 子物体上 Skill_Shard 的字段。 退还 Refund 会退点，但注意是否把 upgrade 清回 None 要对照你当前实现。
  2. unlockedByDefault：节点 Start 就 Unlock，等于「进游戏前配置 + 进 Play 自动写入」。 若 SO 写了默认解锁，但 upgradeType 仍是 None，会出现「以为有技能其实 CanUseSkill 失败」。
  3. 伤害变强从哪来：新分支 SO 里更激进的 DamageScaleData 被 SetSkillUpgrade 换上， 之后爆炸用的就是这份缩放。

场景 10：捡起地上的 Buff

情境：角色碰到漂浮增益球，几秒内攻击变强，到期恢复。

  1. OnTriggerEnter2D 取到 Entity_Stats，对每个 Buff： GetStatByType(type).AddModifier(value, buffName)。
  2. Stat.GetValue 惰性重算：有修正就 base+所有 modifier。 之后普攻/技能再 GetAttackData 时，读到的已是加成后数值。
  3. 到期 RemoveModifier(buffName) 按来源名清掉，销毁球。 生效期间 canBeUsed=false 且精灵透明，防重复吃。

场景 11：传送碎片与生命回溯

情境：第一次 Spell 放下锚点；第二次 Spell 与碎片换位（回溯还会把血量百分比设回放置时）。

  1. currentShard == null：只 CreateShard（回溯分支还会 savedHealthPercent = GetHealthPercent()），通常先不进 CD，方便二次激活。
  2. 再次释放：SwapPlayerAndShard——记下双方位置，碎片移到玩家旧位置并 Explode()（原地炸）、 玩家 TeleportPlayer 到碎片旧位置；然后 SetSkillOnCooldown。
  3. 回溯额外一步：SetHealthToPercent(savedHealthPercent)。 这是「技能状态存在 Skill_Shard 字段里」，不是场景存档。

场景 12：多重充能碎片

情境：解锁 Multicast，可连续扔多次追踪碎片，充能按冷却间隔回复。

  1. currentCharges 初始等于 maxCharges（Awake）。 每次 Handle 成功：Create + 追踪 + charges--；不为 0 时不走普通「整技能 CD 锁死」，而是用充能门闩。
  2. ShardRechargeCo：每隔 cooldown 秒 +1，直到满。 这里把「冷却字段」复用成「回充间隔」。
  3. 爆炸伤害仍是场景 2/3 的管线；变的是能放几次、怎么回复。

场景 13：普攻打开宝箱

情境：砍到箱子，箱子播开启动画并被弹开旋转。

  1. 箱子实现 IDamagable，因此能进普攻的 Overlap 结果里。 TakeDamage 不扣「血条」，而是播 VFX、设 chestOpen、给刚体速度与角速度。
  2. 说明接口设计：战斗检测面向「可受伤」，不绑死 Enemy 类型——技能爆炸若 Layer 包含箱子，同样能开箱（取决于 LayerMask）。

容易混的点

  • 检测 ≠ 索敌：圆/射线只回答「这一帧谁在范围内」；追踪碎片的「最近敌人」才是轻量索敌。
  • 动画事件 ≠ 输入事件：输入决定进哪个状态；刀伤多半在动画事件里结算。
  • SO 配置 ≠ 运行时技能：树节点 Unlock 才把升级数据拷到 Skill_* 组件。
  • 元素瞬间伤 ≠ Debuff：一个在 TakeDamage 里扣，一个在 StatusHandler 里挂。
  • 同一条伤害管线：普攻、技能爆炸、（配置正确时）敌人打玩家，都汇入 GetAttackData → TakeDamage。
