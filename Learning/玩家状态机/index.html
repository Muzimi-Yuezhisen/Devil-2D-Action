模块总览

解决什么问题？ 把玩家所有行为（走、跳、墙滑、冲刺、连击、弹反、死亡）拆成独立状态，每帧只运行一个状态的 Update，切换时统一 Enter / Exit。

  • Player 在 Awake 里创建全部状态实例，Start 时 stateMachine.Init(idleState)
  • PlayerState 注入 input、skills；每个状态的 Update 都会检测 Dash 键
  • 地面 / 空中有中间基类 Player_GroundState、Player_AiredState，复用跳跃、攻击、坠落检测
  • 继承链：EntityState → PlayerState → Ground / Aired / 具体状态
碰撞检测（groundDetected / wallDetected）、SetVelocity、击退等来自 Entity 基类（战斗系统模块）。弹反判定在 Player_Combat。

主要状态切换（简图）

Player.Update() → Entity.HandleCollisionDetection() // 接地 / 贴墙 → stateMachine.UpdateActiveState() → currentState.Update() → 检测输入、速度、timer → stateMachine.ChangeState(新状态) idle ⇄ move （GroundState：无输入 / 有水平输入） ↓ Jump 键 jump → fall → idle / wallSlide wallSlide → Jump → wallJump → fall（Enter 后立即切 fall） 任意状态（CanDash 通过）+ Dash 键 → dashState → idle / fall / wallSlide（撞墙） Ground + Attack → basicAttack → idle（或连击 EnterAttackStateWithDelay） Ground + Counter → counterAttack → idle Air + Attack → jumpAttack → idle HP ≤ 0 → EntityDeath → deadState（禁用输入、关闭物理）

常见问题

为什么连击不直接 ChangeState(basicAttackState)，要用 EnterAttackStateWithDelay？

Animator 的 Bool 参数在同一状态内从 true→false→true 时，有时不会重新触发过渡。HandleStateExit 先把 animBoolName 设为 false，等一帧（WaitForEndOfFrame）再切回 basicAttackState，强制 Animator 读到 false 后再 Enter 设 true，连击动画才能正常衔接。

Dash 为什么在 PlayerState 基类里检测，而不是单独一个「全局状态」？

所有继承 PlayerState 的状态都会先跑 base.Update()，因此在 idle、move、fall、攻击等绝大多数状态下按 Dash 都能响应。CanDash() 排除贴墙、冷却中、已在 dash；dash 状态中 CanDash 返回 false，避免连按。技能冷却在切换时由 skills.dash.SetSkillOnCooldown() 处理。

wallJump 的 Enter 里为什么立刻 ChangeState(fallState)？

蹬墙跳只需要 Enter 里施加一次 wallJumpForce 速度；之后行为与下落相同（空中移动、贴墙再滑等），复用 fallState 的 Update 即可。wallJumpState 的 Update 仅保留「若仍贴墙则回 wallSlide」的兜底逻辑。
